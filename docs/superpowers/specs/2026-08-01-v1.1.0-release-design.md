# v1.1.0 Release Documentation Design

## Goal

Publish the current, tested repository state as v1.1.0 with bilingual release notes and an accurate README status/roadmap. The release must describe every material change delivered after v1.0.0 without claiming unfinished work as complete.

## Documentation changes

- Add a dated `v1.1.0` section to `CHANGELOG.md` and `CHANGELOG_zh.md`, grouped under Added, Changed, Fixed, and Testing.
- Summarize the complete post-v1.0.0 delivery: multi-drive execution, checkpoint/resume, scheduling and policies, cross-platform fixed-drive resolution, platform-specific paths and process hosts, POSIX link/lock semantics, CI hardening, and PowerShell 5.1 compatibility.
- Replace the README's historical strike-through backlog with three current sections: shipped capabilities, active limitations, and prioritized next iterations.
- Keep English and Chinese documents structurally equivalent and correct stale test-count and scheduling statements.

## Release process

1. Make the bilingual documentation changes on `codex/v1.1.0-release`.
2. Validate Markdown links, bilingual section parity, PowerShell parsing, Pester, and the zero-dependency sandbox.
3. Commit and push the release branch, merge it into `main`, then push `main`.
4. Wait for the Windows, Ubuntu, and macOS GitHub Actions jobs to pass.
5. Create and push the annotated `v1.1.0` tag at the verified `main` commit and publish a GitHub Release using the English changelog entry with a link to the Chinese changelog.

## Boundaries

- This release changes documentation and release metadata only; production behavior is not changed.
- Existing known `actions/checkout@v4` Node runtime deprecation warnings remain non-blocking and are listed as maintenance work rather than silently treated as fixed.
- A release is created only from the exact commit that passes the full three-platform CI matrix.

## Verification

- No unresolved placeholders or contradictory shipped/roadmap entries.
- README and CHANGELOG links resolve to tracked files or valid headings.
- English and Chinese documents list the same capabilities, limitations, and release scope.
- Local Pester, parser checks, and sandbox pass before merge; GitHub Actions passes after merge before tagging.
