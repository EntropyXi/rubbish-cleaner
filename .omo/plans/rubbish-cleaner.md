**What you'll get:** 一个可被 Claude Code / Codex / opencode 三大 agent 直接调用的「垃圾文件清理」技能（PowerShell），源码发布在 `github.com/EntropyXi/rubbish-cleaner`（MIT 协议）。给它一个盘符（如 `D:`），它会：① 只读扫描并按类别列出垃圾（临时文件、缓存、日志、空目录、压缩包+解压目录重复件、回收站等，含大小）；② 等你批准后才动手；③ 按安全规则清理——可疑文件**隔离不删除**、被占用文件跳过、junction 感知防误删、7 天内的新文件不碰；④ 生成清理报告（释放了多少、每类多少、跳过了什么、隔离了什么）。配套零依赖测试（装了 Pester 5.x 就用 Pester，没装就用内置沙盒测试，两条路验证同一套行为）和一键安装脚本，装进三个 agent 的技能目录。

**Why this approach:** 沿用上次 C/D 盘清理验证过的同一套架构（经双重审查通过、实际释放 52GB + 17GB、9/9 断言通过），把它从"一次性清理"泛化成"参数化盘符的可复用技能"——安全规则（隔离、跳过锁定、junction 感知、7 天规则、±500MB 容差、证据 CSV）全部继承，你上次会话里验证过的每一条护栏都在。

**What it will NOT do:** 开发期间绝不在真实盘上删除任何东西——所有删除逻辑只在临时沙盒目录里演练，真实盘只做只读扫描。技能本身永远不会删除你的文档、已装软件、Windows 系统组件库、游戏存档、聊天记录；提权系统清理（Windows\Temp、Prefetch 等）只在用户同意并弹 UAC 时尝试，拒绝就安全跳过。

**Effort:** 中等 — 12 个任务、9 个波次，大部分是写脚本 + 测试。
**Risk:** 低 — 所有破坏性逻辑经沙盒测试验证；开发期唯一的真实盘操作是只读扫描。
**Decisions to sanity-check:** ① 命名 `rubbish-cleaner`（你选的）；② 测试双模式——检测到 Pester 5.x 用它，否则零依赖沙盒（你要求的分支 + 原方案）；③ `requirements.txt` 为注释式清单（技能是纯 PowerShell，无 Python 依赖；可选开发依赖 Pester 5.x 以注释写明）——若你本意是要 Python 组件请指出；④ 许可证 MIT（沿用你 aigc-reduce 的惯例）；⑤ 安装到三个 agent 目录 + 更新 opencode 索引；⑥ git 流程：feature 分支开发测试 → push feature → merge 到 main → push main（你的既有约定）。

### Must NOT have (guardrails)
- NEVER run any destructive operation on real user drives during development — all deletion logic tested against fake trees in `$env:TEMP`; the only real-drive operations during development are READ-ONLY scans (dry-run) and the final smoke scan
- NEVER include in the skill: deletion of user documents (Downloads/Desktop/Documents/Pictures/Music/Videos), installed programs, Windows component stores (WinSxS/Installer/DriverStore), pagefile/hiberfil (report-only), game installs, chat data, `.claude`/`.codex`/`.gitconfig`
- NEVER use `-Path` with wildcard-prone paths in skill scripts; ALWAYS `-LiteralPath`; NEVER follow junctions in recursion (PS 5.1 `Get-ChildItem -Recurse` follows NTFS junctions — use the junction-aware `Test-DirEmpty` and reparse-point filtering)
- NEVER permanently delete quarantined files (move to `$env:USERPROFILE\Desktop\.omo\quarantine\<Drive>\` only)
- NEVER run elevated commands without the UAC launcher pattern; elevation denial → `SKIP_ELEVATION_DENIED` logged, wave skipped, continue
- NO `cleanmgr`, NO `DISM /ResetBase`, NO force-killing locked files (skip + log), NO hardcoded drive letters or user-profile paths inside skill scripts (all resolved from `-Drive` / `$env:USERPROFILE` at runtime)
- NO scope reduction: full skill with all categories, both test branches, all three install targets, full git lifecycle
